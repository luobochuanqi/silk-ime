# 01 问题域、需求与约束

本文回答"要解决什么问题"，并给出可验收的需求清单。设计答案见 [02](02-architecture.md)–[08](08-reliability-and-testing.md)；证据来自 [竞品调研](../../research/windows-ime-research-2026.md)（四份报告，快照 2026-11-06）与微软官方文档、开源实现。

## 问题的本质

Windows 中文输入法不是"一个应用"，而是一个**系统级软件基座**：它以 TSF TIP 身份被加载进每一个文本输入宿主进程，参与系统输入管线，同时还要自绘 UI、管理用户数据、可安装可升级。这一形态决定了八个必须解决的问题：

| ID | 问题 | 为什么是问题 |
| --- | --- | --- |
| P1 | 系统集成 | TSF 注册/激活/卸载有严格的 COM + 框架双重注册语义；做错则"输入法不出现" |
| P2 | 安装与分发 | 普通用户可装可卸可升级；DLL 被占用、无签名被拦、缺运行库是品类三大安装故障 |
| P3 | 输入热路径 | 按键→候选在毫秒级预算内完成，且任何情况下不丢键 |
| P4 | 候选 UI | 在任意宿主、多屏、多 DPI、深浅主题下正确出现在插入点旁，不抢焦点 |
| P5 | 引擎与平台分离 | 引擎要可测、可演进、可复用；平台层要可替换、可缩面 |
| P6 | 可靠性 | 进程内代码崩溃 = 宿主应用崩溃；故障必须可降级、可恢复 |
| P7 | 隐私与本地优先 | 输入内容是最高敏感数据；默认零联网、数据可迁移、卸载不丢数据 |
| P8 | 可观测性 | 崩溃与兼容性问题必须可诊断，否则无法支撑宿主矩阵 |

## 目标（基座范围）

基座 = "能作为输入法被系统正确加载、正确输入、正确显示、正确安装的最小可靠底座"：

- 全拼 + 简拼输入、整句转换、模糊音、智能标点、中英切换、翻页选择、用户词频自适应、自定义短语；英文输入：直通 + 单词补全。
- 候选窗（默认进程外渲染 + `host_render` 兜底）。
- per-user 安装（免管理员）+ per-machine 完整模式；升级、卸载全流程。
- x64 + arm64。

## 非目标（基座不做，留缝）

双拼/五笔/码表、U/V 模式、英文拼写纠错、繁简转换、云候选、AI 帮写/联想、语音、皮肤、云同步、自动更新、设置图形界面。理由：微软拼音以免费、无广告、预装定义了零成本基线，基座的竞争切入点是"可靠、干净、轻"，功能面由后续版本按证据逐项展开；前沿技术的接入缝见 [05](05-engine.md) 排序器。

## 功能需求

| ID | 需求 | 验收 |
| --- | --- | --- |
| R-1 | TSF 注册/激活/卸载，per-user 与 per-machine 双作用域 | 干净 VM 安装后 Win+空格可见、可切换、可卸载 |
| R-2 | 按键→候选→上屏热路径 | p95 ≤ 30 ms（端到端，05 预算） |
| R-3 | 中英文输入面（目标节清单） | 黄金语料全过（05） |
| R-4 | 候选窗跟随插入点 | 03 宿主矩阵全类别的定位与显隐正确 |
| R-5 | 引擎无 Windows 依赖 | `go test` 在非 Windows 平台可运行 |
| R-6 | 安装/升级/卸载安全 | 升级免重启（改名占位）；卸载保留用户数据 |
| R-7 | 故障降级不丢键 | 08 降级矩阵逐行演练 |
| R-8 | 本地数据、默认零联网 | 无网络代码路径；用户数据纯文本可迁移 |
| R-9 | 文本配置 + 可手改词库 | `silk.toml`/`userdict.txt` 改后重载生效 |
| R-10 | 本地日志与诊断导出 | 日志无用户文本；一键导出诊断包 |
| R-11 | 性能预算全项达标 | 05/06 预算表逐项测量记录 |
| R-12 | x64 + arm64 发布 | 双架构 VM 验证 |
| R-13 | 宿主兼容矩阵验证 | 03 矩阵签核；08 回归基准全过 |
| R-14 | 演进缝真实存在 | 排序器/方案描述器/更新器接口在设计中可指认，无实现 |

## 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 按键热路径见 R-2；单帧渲染 ≤ 8 ms；冷启动到首候选 ≤ 150 ms；引擎堆 ≤ 30 MB |
| 可靠性 | 进程内代码面最小；降级矩阵完备；升级失败可回滚 |
| 隐私 | 默认零联网、零遥测、零广告/推荐管道；日志仅元数据；卸载保留用户数据 |
| 兼容 | Win10 21H2+ / Win11；03 宿主矩阵 |
| 可维护 | 引擎/平台/UI 三缝清晰；协议版本化；文档与行为同步 |

## 约束与假设

- 语言与形态：Go（引擎/宿主）+ Rust（TSF 适配与渲染库），GPL-3.0。
- TSF 是唯一输入 API（微软已阻止 IMM32 实现的 IME）。
- Win10 仍在存量市场（2026-08 中国桌面 44.67%）且微软已停止其功能演进——支持 Win10 既是用户基数也是窗口期，放弃它等于放弃一半市场。
- 签名证书可获取（个人/开源开发者证书路径存在）。

## 证据摘录（设计约束的来源）

来自四份竞品调研 + 官方文档的五条硬约束，逐条塑造了架构：

1. **进程模型无第二解**：Weasel、PIME、水杉、青简、清风、0c、墨奇独立收敛到"极薄 TSF DLL + 命名管道 + 单例引擎进程"；Go 引擎服务有墨奇与 0c 的生产验证（0c 本机重排 P95 7–16 ms）。→ ADR-1/2/4。
2. **发布工程是一等公民**：无签名 = SmartScreen/杀软误报（注入行为似恶意软件）；DLL 占用 = 升级重启；UIAccess = 签名 + 受信任目录约束安装路径；反作弊游戏拒载第三方 IME。→ ADR-3、07 全篇、03 兼容矩阵。
3. **微软拼音是零成本基线**：免费、无广告、无账号、预装、本地默认。"干净"是及格线不是卖点；差异化只能靠长句准确率、排序质量与稳定性。→ 01 目标/非目标的范围切分。
4. **开箱即用与可迁移数据是产品前提**：雾凇拼音（开箱配置）20,050★ 是 Weasel（框架）8,263★ 的 2.4 倍；配置门槛（"重新部署/重开/重启"语义）是 Rime 生态第一痛点；竞品卸载删用户词库引发数据丢失投诉。→ ADR-5/7、07 卸载策略。
5. **默认值即产品立场**：行业隐私"两档模式"乱象（某头部产品隐私承诺与实际遥测文档自相矛盾、云候选默认开把拼音发往第三方）是反面教材；青简/清风/DIME 的"默认关、纯本地、可核对"是正面样板。→ R-8、08 可观测性约束。

实现级约束（来自同一批证据）：零运行库依赖（缺 VC++ 是头号安装故障）、不内嵌脚本运行时（PIME 内嵌运行时的 CVE/RCE 账单）、模型资产不进主包（318 MB 安装包反例）。

## 风险清单

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Rust 产 Arm64X DLL 工具链不成熟 | arm64 发布形态受限 | O-1 先行验证；退路是双 DLL（x64+arm64） |
| `GetTextExt` 跨宿主语义差异 | 部分应用定位偏差 | O-3 探针实测；偏差登记已知问题 |
| 双渲染路径的长期一致性 | 维护成本 | 渲染实现单库（ADR-3）；共享用例 |
| 高完整性宿主连不通中完整性 host | 提权应用退化英文 | O-4 验证；退路是提权场景直通 + 文档声明 |
| 签名证书获取周期 | 阻塞发布 | 证书申请与 M0 并行 |
| Win10 长尾兼容 | 支持成本 | 兼容矩阵明确 Win10 21H2+ 基线 |
