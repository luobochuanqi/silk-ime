# Windows 中文输入法：清风、水杉与细分赛道竞品调研

> 检索与核验日期：**2026-11-06**（全部在线数据为当日快照）。
> 范围：**仅限有当前 Windows 版本支持证据**的中文输入法，重点为清风输入法（WindInput）与水杉输入法（Metasequoia IME / MSIME），并覆盖五笔/音形、形码、本地 AI、纯净向等细分产品。
> 本文与 [`input-method-landscape-2026.md`](./input-method-landscape-2026.md) 互补：那份报告覆盖移动端与全球格局，本文只做 Windows 桌面的竞品纵深，不重复其移动端数据。

---

## 1. 结论摘要

1. **Windows 桌面输入法没有可信的市占率数据。** 本次能核实的唯一 PC 端口径数字是 QuestMobile 2026 年 9 月榜单中的「搜狗输入法 PC 端合计活跃用户 3,529.80 万」，且只有一家厂商、没有分母、没有其他输入法的对应数字，**不能换算成份额**。本报告不做任何 Windows 份额排名。
2. **清风与水杉是当前最有参考价值的两个「新势力」，且路线相反。** 清风（WindInput）是五笔/码表优先、**完全没有云端与 AI** 的 GPL 开源产品；水杉（MSIME）是拼音/双拼优先、**默认开启云候选并内置神经整句重排**的 GPL 开源产品。两者都写 TSF、都自研引擎、都把「隐私边界可被读代码检查」写进官网，但对「AI 该不该进输入法」给出了对立答案。
3. **「纯净 + 本地」已从道德主张变成可量化卖点。** 冰凌、可可、清风都把「无广告、无捆绑、不上传输入」写在首页；水杉把「哪些数据会离开设备」做成一张逐平台表格。这抬高了新入者的信任门槛：笼统说「重视隐私」不再有效。
4. **形码/码表赛道仍由 2000 年代产品与个人开发者把持，且有明显的分发脆弱性。** 小鹤音形的官方域名 `flypy.com` 已过期（现址 `flypy.cc`），Windows 包在该站只能通过网盘取得；花儿五笔的官方域名同样失效。**同名、仿冒站点是这一赛道的真实风险**，冰凌官网为此专门挂了防伪公告。
5. **五笔用户的真实痛点是「平台」而非「拼音准确率」。** 冰凌能同时挂 86/98/新世纪五笔与郑码，清风能导入虎码等第三方码表——这类「码表平台」需求在拼音厂商那里长期得不到满足，是 Silk 若要扩展方案体系时的现实参照。
6. **本地小模型已经能在输入法里跑，但收益是「窄而可测」的。** 水杉公开了 4.5 MB / 25.5 MB 重排模型的评测（56 句样本首选正确 41 → 49 → 52），并明确写了「52 句上差三句以内是统计噪声」。这是本领域少见的、诚实的 AI 效果披露，比任何「AI 加持」宣传都更值得学。
7. **对 Silk 的定位建议：** 以「Windows 基础输入 + 本地优先 + 低干扰 + 可验证的隐私边界」为主轴，把 AI 限制在候选重排这类**可关闭、可测量、可降级**的窄场景；不要把皮肤市场、社区、账号同步、语音全家桶当作第一版目标。

## 2. 检索方法与证据口径

### 2.1 来源优先级

按以下顺序取信，低优先级来源只用作线索：

1. 产品官网、官方文档站、官方更新日志、官方仓库与 Release；
2. Microsoft Learn 等平台方文档；
3. 可信数据机构原始报告或其被完整引用的图表；
4. 第三方软件站、论坛帖、转载文章——**仅作线索与热度旁证，不用于核心事实**。

### 2.2 指标能说明什么

| 指标 | 能说明 | 不能说明 |
|---|---|---|
| GitHub stars | 社区关注度、被推荐频次 | 用户数、Windows 份额 |
| GitHub Release 资产下载量 | 经该渠道的分发量级（含重复下载、CI、镜像） | 装机量、活跃用户、留存 |
| 官网自报「累计下载」 | 厂商自述的分发规模，含各平台与镜像 | 安装人数；水杉官网自己也写明「不代表安装人数」 |
| 论坛帖浏览量/回复数 | 单点讨论热度 | 用户规模 |
| PC 端 MAU（QuestMobile 等） | 特定厂商在特定口径下的活跃规模 | 全市场分母、份额、默认使用率 |

**明确声明：本次未找到任何可信的 Windows 中文输入法市占率数据。** 下文所有数字均为单一维度的代理指标，不做加权、不做排名换算。

### 2.3 排除规则

- 无当前 Windows 版本证据者不进入对比（见第 6 节）。
- 官方渠道不可达、只能经第三方下载站获取的产品，标注为「不可核实」而非「已停更」——两者结论不同。
- 同名产品以官方仓库/官网的自我描述为准，不采信下载站的介绍文案。

| 码表方案仓库 | <https://github.com/huanfeng/WindInputCodeTable> | 正常（五笔 98、新世纪、虎码等） |

**避开同名陷阱：** 搜索「清风输入法」会命中若干转载站与聚合页（如 `zhibanku.com`、`xywork.work`、`zendot.org`），其中部分页面把许可证写成 MIT、把系统要求写成「Windows 7/8/10/11、32+64 位」。**官方文档明确写的是 Windows 10 / 11（64 位）**，且许可证自 v0.127.0 起为 GPL-3.0-or-later（此前版本为 MIT）。以官网与仓库为准。

### 3.2 定位与目标用户

- 自我描述：「轻量、快速、可定制的开源中文输入法」，**专为五笔和码表输入方案设计**（[README](https://github.com/huanfeng/WindInput)）。
- 目标用户：五笔 86 用户、需要五笔/拼音混输的用户、以及要挂自有码表（98 版、新世纪、虎码、郑码类）的形码玩家；同时提供全拼与双拼，使双拼用户也能用。
- 不是「开箱即用的拼音输入法」：官方文档把方案选择放在「装完先做这三件事」里，说明方案体系是产品的一等公民。

### 3.3 技术与系统要求

| 项目 | 内容 | 来源 |
|---|---|---|
| 系统要求 | Windows 10 / Windows 11（64 位） | [安装与激活](https://windinput.com/docs/start/installation) |
| Windows 框架 | 纯 TSF（`wind_tsf`，C++） | README 组件表 |
| 核心引擎 | Rust（`wind_input`），跨平台；macOS 走 IMKit，Linux 走 Fcitx5（预览） | README |
| 安装形态 | 标准安装（注册 TSF、开始菜单、开机启动）／便捷模式（绿色，`wind_portable.exe` 注册组件） | 安装文档 |
| 数据位置 | 默认 `%APPDATA%\WindInput`；**用户数据自 v0.127.0 起为纯文本文件**（`data\` 下可编辑器手改，复制目录即迁移） | 更新日志 v0.127.0 |
| 签名 | 程序与安装包已数字签名；SmartScreen 仍需下载量积累信誉，新版本初期可能拦截 | 安装文档「已知问题」 |
| 安装包体积 | 未在官方页面公布；Release 资产名显示为 `WindInput-Setup-*.exe` 与 `WindInput-Portable-*.zip` | Release |

### 3.4 输入方案与核心功能

- **方案**：内置全拼、双拼、五笔 86、五笔拼音混输；双拼布局涵盖小鹤、自然码、微软、智能ABC、拼音加加等；第三方码表通过 WindInputCodeTable 导入（五笔 98、新世纪、虎码）。
- **四种引擎并列**：文档的「方案设置」分为**码表 / 拼音 / 混输 / 英文**四类，每类有独立全局配置；方案设置页还标注了「0.131 新增 · 方案级码表配置」，即把全局项改为单方案专用。
- **面向形码用户的细节**（这是它区别于通用拼音输入法的地方）：
  - 码表整句输入（实验性，出厂关闭）；
  - 满码唯一自动上屏、空码处理、顶码；
  - 辅助码（内置两套「首右」形码辅助码，v0.130.0）；
  - 编码栏跟随高亮候选切分显示、候选注释模板、`${correct_pinyin}` 正确拼音提示；
  - 剪贴板整串反查、`dict.rev` 反查。
- **面向日常输入的补齐**：拼写纠错（字母打反/漏打，纠错候选带 `*` 且不抢首选）、误读提示、模糊音、简拼、英文候选与补全、emoji 与符号、命令短语（`date`/`time`/`week` 等）、候选展开成多行、Caps Lock 短按切中英。
- **设置与运维**：图形设置程序（`wind-setting`）、命令行工具、输入统计（默认需手动开启）、备份还原、按应用独立配置与兼容性规则。

### 3.5 AI、语音与云能力

**没有。** 这是本次调研中最干净的结论：

- 官方更新日志全量检索「AI」「云」「联网」「在线」「上传」等关键词，仅有 2 处「在线」且分别指「Linux 在线升级」与「飞书在线表格」的兼容性修复，**未出现云候选、AI 联想、语音输入、账号体系**。
- 官网「支持项目」页自述：「清风输入法开源免费，没有广告和内购」，赞助用途中也没有服务器/API 成本项之外的 AI 服务支出（[支持项目](https://windinput.com/sponsor)）。
- 唯一与网络相关的功能是**可选的「主题与方案市场」下载**与文档/主题包获取，属于用户主动触发的资源下载，与输入内容无关。

> 判断：清风用「**不做云端**」换取了最简洁的隐私叙事，代价是无法提供跨设备同步与云端词库。

### 3.6 隐私与联网边界

| 边界 | 状态 | 依据 |
|---|---|---|
| 输入内容上传 | 无相关功能 | 更新日志/文档无云候选与统计上报 |
| 输入统计 | 本机 `data\stats\`，**仅记录字数、类别、码长、选第几个候选等元数据，不记录具体内容**，可关闭 | [统计功能](https://windinput.com/docs/settings/stats) |
| 日志 | 本机日志目录，可打包/清理 | 安装文档、v0.127.0 条目 |
| 用户数据可迁移性 | 纯文本、可手改、可整目录复制 | 更新日志 v0.127.0 |

这一组合（元数据统计 + 纯文本数据 + 无云端）是本报告里最容易被审计的隐私设计。

### 3.7 广告与打扰

无广告、无弹窗、无内购（官方自述）。安装向导会创建开机启动与开始菜单项，属于常规集成而非打扰。唯一的「打扰」风险是 SmartScreen 拦截与杀软误报，官方在文档中给了处置说明（属误报）。

### 3.8 账号与同步

无账号体系。同步通过「复制用户目录 / 导入导出」在本地完成，市场资源（主题、方案包）为公开下载物，不绑定身份。

### 3.12 优点与局限

**优点**

- 五笔/码表能力在开源 Windows 输入法里最完整（多版本五笔 + 混输 + 码表导入 + 辅助码）。
- 纯本地、无云端、无账号，隐私边界可用「无相关代码路径」来论证，而不是靠承诺。
- 用户数据纯文本、可手改、可整目录迁移，工程上非常「可救」。
- 安装/便携双形态、数字签名、命令行工具、按应用兼容性规则，产品化程度高于多数个人项目。

**局限**

- 无云同步、无跨设备词库，多机用户需自行搬运。
- 拼音不是主战场：整句与智能纠错能力仍在补齐（码表整句标注为实验性）。
- 更新频繁且含破坏性变更，需要用户跟版本、跟重启。
- 单手维护（7 位贡献者），bus factor 明显；macOS 未签名、Linux 仅预览。
- Windows 10/11 64 位起步，放弃 Win7/32 位（冰凌、水杉仍覆盖这些场景）。

### 3.13 对 Silk 的启示

- **「不做云端」可以是一个完整的产品主张**，前提是把本地能力（码表、辅助码、反查、纠错、统计）做到不需要云。
- **把用户数据做成纯文本 + 可整目录迁移**，是低成本高信任的设计；比自建同步服务便宜得多。
- **方案/引擎分层 + 方案级覆盖**，是支持多输入体系又不把设置页炸掉的有效手段。
- 值得抄的具体点：拼写纠错候选带标记且不抢首选；统计只记元数据并可关闭；安装向导把「数据目录」一次性问清。

**重要结构说明（易被误读）：** 水杉在 Windows 上有**两条并行产品线**，官网下载页把二者并列但它们的默认联网设置不同：

| 产品线 | 来源 | 状态 | 数据目录 |
|---|---|---|---|

### 4.2 定位与目标用户

- 自我描述：「一款开源的自由 Windows 输入法，面向 Windows 10 / Windows 11，采用纯 TSF 方案」（`msime-windows` README）；项目理念为「**开箱即用、输入体验简洁、设置便捷、响应迅速**」（[关于](https://msime.app/about/)）。
- 目标用户比清风更宽：拼音/双拼为主、可选五笔、**候选旁直接显示译文**（中↔英/日/法/西/俄/德/韩），并带日语罗马音输入。实际上同时覆盖三类人：普通拼音用户、双拼/辅助码用户、以及「边打字边学外语」的人群。
- 与青简（见 5.5）在「候选旁显示译词」上高度重叠，是这一细分里最直接的竞争关系。

### 4.3 技术与系统要求

| 项目 | 内容 | 来源 |
|---|---|---|
| 系统要求 | Windows 10 / 11；Server 与设置程序均为 64 位 | [Windows 指南](https://msime.app/docs/windows/) |
| 必备运行库 | **Microsoft Visual C++ 2015–2022 Redistributable（x64）**；设置页另需 Edge WebView2 Runtime | 同上、下载页 |
| Windows 框架 | 纯 TSF（正式版）；候选窗自绘，不依赖宿主应用配合 | README、功能页 |
| 进程结构 | `MetasequoiaImeServer.exe`（Server）+ `MetasequoiaImeWatchdog.exe`（看门狗，登录自启、崩溃拉起） | Windows 指南 |
| 安装包签名 | 有数字签名，签署者 `Open Source Developer LU FAN`，机构 Certum；发布页给出 SHA256 与 GitHub build provenance | [关于](https://msime.app/about/)、下载页 |
| 遗留平台 | 另有 Windows 7 构建（官网列「Windows 7 累计下载 269」） | 官网首页 |

**引擎分层**：把拼音/双拼/多语言输入引擎单独发布为库（Rust crate `msime-engine`，MPL-2.0；C ABI 预编译归档），可被其他输入法嵌入；同一引擎编译为 WebAssembly 供网页使用（[引擎库](https://msime.app/engine/)）。这是本报告里唯一把「引擎即产品」做出来的中文输入法。

### 4.5 AI、语音与云能力

水杉是全样本里 AI 化最激进的 Windows 输入法，也是披露最具体的：

- **神经联想（整句重排）**：不开时不产生候选，只在引擎已给出的几种整句读法里重排首选；模型来自 `chinese-ime-lm`。
  - 快速模型 **4.5 MB** / 425 万参数，单候选字 0.33 ms，每次按键都跑；
  - 高精度模型 **25.5 MB** / 2,486 万参数，单候选字 2.0 ms，停顿时接手；
  - 评测为 **60 句手写用例**，首选正确：引擎原序 41 → 快速模型 49（救回 10、弄错 2）→ 高精度 52；候选池内理论上限 52。
  - **官方自己写明**：「样本只有 60 句，两个模型之间的名次差异在统计噪声里」「52 句上相差三句以内是统计噪声（McNemar 精确检验 p≈0.25）」（[神经联想](https://msime.app/model/)）。
- **AI 候选联想**：需用户自填服务商凭据，未填不发请求。
- **候选翻译**：本地词典优先；在线走腾讯云 TMT / 小牛翻译 / 自建 DeepLX，或「水杉账号」。
- **语音输入**：需配置服务并主动触发；可选云端或本地模型。
- **注意能力边界**：模型只用于拼音输入，五笔版与日语等单一方案版本不带手机端模型。

### 4.6 隐私与联网（逐项核对，这是水杉最值得学的部分）

官网把「哪个功能会联网、默认开还是关」做成逐平台表格，并标注更新日期。Windows 正式版（`msime-windows`）：

| 功能 | Windows 正式版默认 | 会发送什么 |
|---|---|---|
| **云候选** | **默认开启**，首次安装可取消勾选 | 当前输入的**拼音串**发往 `inputtools.google.com`；不含已上屏正文、词库、调频数据 |
| AI 候选联想 | 需自填凭据，无凭据不请求 | 拼写 + 功能所需上下文 |
| 候选在线翻译 | 需配置腾讯云等凭据 | 待翻译候选文本 |
| 语音输入 | 需配置并主动触发 | 录音（选用云端时） |
| 匿名使用统计 | **不发送** | — |
| 检查更新 | 仅手动点击时联网 | — |
| 本机数据 | `%LOCALAPPDATA%\metasequoiaime\`；**API 凭据以明文保存在 `config.toml`** | — |

「Windows 新版预览」与其它平台默认值不同：云候选新装默认关闭、匿名统计默认开启（可在「关于」页关闭）、首次启动注册匿名账号、后台约每天查一次 GitHub Releases（只提示、不下载）。

隐私政策还明确了几条可作为行业标尺的细节：云剪贴板**文本在设备端加密**、服务端只存密文；密码框与私密输入框不学习、不写日志、不发 AI；删除账号会级联删除同步数据与社区内容；**但**在线数据库备份副本的保留期限未公布。

### 4.12 优点与局限

**优点**

- Windows 上功能密度最高：双拼方案齐全、辅助码成体系、混输、翻译、日语、语音、手写、屏幕键盘、MCP 接口。
- **隐私披露做到了「可核验」级别**：逐功能默认值 + 发送内容 + 关闭路径 + 原始 `PRIVACY.md` 链接。
- 工程规范：数字签名 + SHA256 + build provenance；文档逐版本对源码；TSF 端有看门狗。
- 引擎独立成库并开源（MPL-2.0 + Apache-2.0 权重），对生态友好。
- AI 效果公开评测、公开负结果、公开「不显著」的结论——**这在这个行业极罕见**。

**局限**

- 默认开启云候选（拼音串出境），对「零联网」要求者是硬伤；必须由用户主动关闭。
- 依赖 VC++ x64 运行库与 WebView2，安装失败的第一大原因就是缺 x64 运行库（文档专门用一整节讲）。
- 功能极多导致设置项密集，与「轻量低干扰」的直觉相冲突。
- 两套 Windows 实现并行，行为差异与维护成本是长期负债；Issue 积压 358。
- 社区/账号/云同步等在线服务绑定了公司主体与服务器，属于「不可自托管」的部分。
- 语音、在线翻译、AI 联想都需用户自备 API 凭据，实际可用性依赖外部服务。

### 4.13 对 Silk 的启示

- **「默认值就是立场」**。水杉把云候选默认开到「正式版」，就必须用一张表来解释；Silk 若主张本地优先，默认值应反过来，把每个联网项都做成显式 opt-in。
- **AI 效果要说清代价与噪声**。水杉的 4.5 MB 模型（每次按键 0.33 ms/字）与「60 句样本、差三句是噪声」的自我限定，是可以直接对标的披露标准。
- **模型可替换、可删除、可关闭**，且明确「引擎没拼出的候选，模型选不到」——把 AI 限制在重排而非生成，是风险最低的形态。
- **不要把两套实现长期并行**；也不要把「必须装某个运行库」变成用户的第一道坎。
- 可借鉴的具体点：MCP/命令行接口（让输入法可被脚本与 AI 客户端调用，但默认不授予词库读写）；发布页给 SHA256 与 provenance；隐私页逐项列默认值。

## 9. 对 Silk IME 的启示

### 9.1 应当借鉴

1. **把「默认值」当作产品声明。** 清风用「没有云端代码路径」赢得信任；水杉用「云候选默认开 + 一张逐项表」赢得透明。Silk 的正确姿势是第三种：**每个联网能力默认关闭，开启时明示发送内容，并在设置里给出即时关闭入口**。
2. **AI 只做重排，不做生成。** 水杉的 4.5 MB 模型（0.33 ms/字，每次按键都跑）与知意的前文重排，都证明小模型的收益可测、成本可控。同时水杉与知意的模型在 52 句样本上只差 2 句（噪声内）——**模型不必大，也不必自研到极致**。
3. **披露代价与噪声。** 学水杉：给出样本量、给出「救回几句/弄错几句」的分项、明确写「差三句以内是噪声」。这比任何准确率百分比都更有说服力，也保护自己不被告虚假宣传。
4. **用户数据纯文本、可整目录迁移。** 学清风 v0.127.0 的做法：文本文件、可手改、写坏不覆盖、复制即迁移。这让「退出成本」和「信任成本」同时下降。
5. **统计只记元数据、默认关闭、可清空。** 清风的字数/码长/首选率/速度四类指标已足够做产品改进，不必记录内容。
6. **隐私边界要可验证到条目级。** 学水杉：逐功能列出「是否联网、默认状态、发送什么、怎么关」，并附原始 `PRIVACY.md` 链接。
7. **码表可导入 + 辅助码 + 反查 + 调频** 是承接形码用户的最小集（冰凌、清风、wubi-lex 三方印证）。
8. **发布可信度工程**：数字签名、SHA256、build provenance、可核对的安装包大小（冰凌直接说「安装向导不超过 4MB，超过就是假的」——这种可自证的说法极有效）。
9. **方案文件应可导出、可被他人挂接。** 小鹤双拼被系统与商业输入法内置，说明开放方案的传播力远超单一产品。

### 9.2 不应跟风

1. **不要做皮肤/方案/插件市场。** 清风、水杉、冰凌都在做，但这带来审核、托管、CDN 与信任成本；Silk 的第二版不需要。
2. **不要做社区 + 账号 + 云剪贴板。** 水杉为此承担了公司主体、用户协议、加密密钥、备份删除策略等一整套合规负担，与「轻量」直接冲突。
3. **不要做语音与在线翻译。** 高质量离线中文 ASR 的模型体积与维护成本远超收益；在线翻译又把输入内容送出境。水杉与青简都证明这两项需要用户自备凭据，实际使用率可疑。
4. **不要复制「候选旁译词」这一细分。** 水杉与青简已经正面相撞，且青简的实测表明「学习功能必须不为输入效率让路」——这是一个高投入、窄受众的战场。
5. **不要并行维护两套 Windows 实现。** 水杉为此付出长期一致性与 Issue 积压成本（358 个未关闭 Issue）。
6. **不要让用户先装运行库。** 水杉的头号安装故障是缺 VC++ x64；Silk 应静态链接或自带依赖。
7. **不要做交叉推广、推荐位、弹窗促销。** 万能五笔是明确的反面样本；Silk 的目标用户正是从这类产品迁出的人。
8. **不要把 `Win7` / `32 位` 当作差异化去追。** 冰凌与水杉的 Win7 构建下载量都极低（水杉 Win7 仅 269 次），投入产出不成比例。
9. **不要用「AI 加持」当卖点。** 本样本中没有一个成功案例是靠 AI 宣传取胜的；水杉的 AI 页超过一半篇幅在讲「哪里不显著」。

### 9.3 一句话定位建议

> Silk 的机会不在「更聪明的输入法」，而在**「一个默认不联网、数据在自己手里、出问题时你能看懂它做了什么」的 Windows 输入法**；AI 只作为可关闭的候选重排存在，并公开它的测量方法与代价。
