下面按“**学习/进化侧**、**推理/时效侧**、**架构/隐私基础设施**”整理可应用于输入法的技术，以及它们分别对应输入法的什么 feature。

### A. 模型学习/进化类技术

| 技术                                 | 对应输入法 feature                                                               | 说明                                                                                             |
| ------------------------------------ | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **联邦学习（Gboard 生产级）**        | 下一词预测、智能撰写 Smart Compose、候选词实时重排序 OTF rescoring、搜索查询建议 | 原始输入不出端，只上传模型更新；Gboard 已在超 10 亿设备规模部署                                  |
| **DP 联邦学习 / DP-FTRL**            | 下一词预测、智能撰写等语言模型训练                                               | 给联邦训练加形式化差分隐私保证，限制单用户数据对全局模型的影响                                   |
| **TEE 可验证联邦学习**               | 同上，偏训练/聚合基础设施                                                        | 加密数据只在可信执行环境内解密聚合，可审计、可复现构建；不直接改变前端 feature，但提升训练可信度 |
| **华为 MindSpore Federated**         | 输入法表情图片预测/推荐                                                          | 根据聊天文本在本地推荐表情，支持大规模终端部署                                                   |
| **Rectfly“联邦评测”**                | 候选词/联想质量优化                                                              | 用户只反馈“这个联想对不对”，不上传原始输入，用评测结果优化全局模型                               |
| **端侧持续学习（LoRA 增量微调）**    | 个性化下一词、纠错习惯、候选偏好                                                 | 用户确认/纠正作为本地信号，后台空闲时微调 LoRA；不碰实时推理主路径                               |
| **Synapse：冻结主干 + 外挂习惯记忆** | 输入惯例记忆、个性化联想/补全                                                    | 主干模型不动，用低秩突触存储用户反复出现的输入习惯，避免灾难性遗忘                               |
| **SacFL：联邦持续学习**              | 分布漂移检测后的个性化增量学习                                                   | 设备自主检测输入分布变化，触发增量学习或防御策略，兼顾个体自进化与群体协同                       |

### B. 推理/时效类技术

| 技术                                   | 对应输入法 feature                  | 说明                                                                                             |
| -------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------ |
| **端侧 AI 推理 / 端云混合架构**        | 候选词生成、下一词联想、低延迟补全  | 高频轻量任务在端侧毫秒级完成；云端只做复杂补充。实测端侧可到 18–50ms 量级，云端往返常 120–340ms  |
| **端侧轻量语言模型**                   | 下一词预测、候选排序                | Gboard 经典 NWP 模型约 140 万参数；OTF 模型约 240–640 万参数，专为端侧低延迟设计                 |
| **热词注入 + 候选重打分**              | 新词候选、新闻热词联想、时效性补全  | 模型权重不动，维护轻量热词表，在解码/重排序阶段给热词临时加权；对 <50ms 推理影响很小             |
| **联邦分析**                           | 新兴术语感知、趋势性下一词/联想偏置 | 设备端只上传聚合统计量，服务器识别群体语言漂移，再以轻量偏置信号调整预测/解码                    |
| **LLM + 检索增强（如 Wisdom-Weasel）** | 深度联想、生成式候选、上下文补全    | 可用本地推理结合本地检索知识；算力和延迟要求高，更适合作为可选“深度联想”模式，而非默认毫秒级路径 |

### C. 架构/工程结论

| 结论                                  | 对应影响                                                                    |
| ------------------------------------- | --------------------------------------------------------------------------- |
| **“端侧推理为主、云端/异步学习为辅”** | 推理侧保障候选词和联想低延迟；学习侧可异步、空闲充电时完成                  |
| **自进化与时效性分层**                | 自进化层管长期个性化；热词注入/联邦分析管短期时效性；两者不干扰实时候选路径 |

### 总结

输入法应具备“自进化”能力：一是能够根据用户的个人输入习惯持续学习与适配，实现个性化自进化；二是能够基于大范围用户习惯进行学习，提升整体输入体验；三是能够及时反映网络语言与表达的最新变化，保持词汇和表达方式的时效性。
