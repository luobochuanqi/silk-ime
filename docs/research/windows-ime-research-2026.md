## 先说数据边界

**没有找到可信、可横向比较的 Windows 中文输入法市占率。** 因此本调研不做份额排名：

- QuestMobile 2026 年 9 月 PC 应用榜中，搜狗输入法以 3,529.80 万合计活跃用户成为唯一入榜的第三方输入法，但榜单没有市场分母，也不统计系统内置的微软拼音，不能换算成份额。
- 易观、MobTech 的中文输入法数据主要是移动端第三方 App 口径，不能外推到 Windows。
- GitHub stars、Release 下载量、官网自报下载量分别反映社区关注和特定渠道分发，均不等于装机量或活跃用户。

## 横向结论

1. **主流市场的竞争点已从“有没有拼音”转向基础质量、默认隐私和低干扰。** 全拼、双拼、自定义短语已是标配；AI 帮写、语音和内容服务很热闹，但并不能替代整句准确率、候选排序和宿主兼容。
2. **微软拼音是不可绕过的基线。** “免费、干净、本地”本身不足以让用户切换；Silk 必须在长句、候选手感、稳定性或可控性上给出可感知收益。
3. **开源生态的在位者与新势力各有缺口。** Weasel 有生态但交付门槛高；青简、水杉、清风产品化更快，但维护者集中、发布与兼容工程仍在成熟。Silk 不应再做一个需要手工部署的 Rime 前端。
4. **清风和水杉代表两条相反路线。** 清风以无云端、码表能力和文本数据建立信任；水杉以本地神经重排和丰富功能增强输入，但 Windows 正式版默认开启云候选。两者都值得借鉴，不能混成同一种“开源即离线”的叙事。
5. **Windows 平台工程是共同难点。** TSF DLL 被宿主占用导致升级重启、代码签名与 SmartScreen、UIAccess 与候选窗层级、游戏反作弊、高 DPI/Electron/远程桌面兼容，都是首版就要面对的产品能力。
6. **AI 最有价值的落点是窄而可测的候选增强。** 本地整句纠错/重排、显式触发的语音后处理比输入法内嵌全能助手更符合 Silk；必须可关闭、可降级，核心输入离线可用。
7. **隐私需要落实为可审计的默认状态。** 逐功能说明发送什么、发到哪里、默认是否开启、如何关闭；敏感输入不学习，凭据安全保存，用户数据可导出、备份和彻底清除。

## 对 Silk 的优先级建议

1. **先赢基础输入与 Windows 兼容**：整句与候选质量、薄 TSF 壳 + 独立引擎服务、按应用兼容规则、安装/升级/卸载可靠。
2. **把发布工程当产品**：代码签名、校验和、稳定发布节奏、明确支持 Windows 10/11；不要等“稳定以后”再补。
3. **默认本地、无商业位、无强制账号**：更新检查、云候选、同步和 AI 分别授权，不用一个总开关掩盖不同数据流。
4. **AI 先只做候选重排/纠错**：小模型、本地运行、公开评测、失败自动回退；暂不投入语音全家桶、皮肤市场、社区和云账号。
5. **保留低门槛的可控性**：图形设置覆盖普通用户，文本配置与可迁移词库服务高级用户；避免 YAML patch 式部署成为使用前提。
